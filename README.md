# 奇瑞签到

## v2.1.0：恢复原版，只修签到请求

以用户最初提供的 fmz200 奇瑞汽车 App 签到脚本为基准，**恢复原来的任务逻辑、详细日志、通知方式和 Env 框架**。不再使用 v2.0.0 的重写任务框架。

原脚本里的实际修改仅有三处，都在 `completeSignTask()` 内：

1. 原 URL query 加密后放入 `encryptParam`。
2. 请求头增加 `encryptFlag: true`。
3. 原来的 `{"eventCode":"SJ10002"}` 请求体加密后发送。

此外附加必需的加密工具（内嵌 CryptoJS 4.1.1），不动态下载执行代码。共享常量来自公开 H5 客户端，不是任何人的账号 token。

**文章获取、分享、账号并发处理、原来已有的请求格式、响应解析和通知逻辑不再改动。**原脚本的潜在边界行为同样保留，不在本次修复中顺便重构或“优化”。

## 更新原任务

原脚本地址不变，在 Loon 更新/重新下载这一项即可：

```text
https://raw.githubusercontent.com/W925666/qirui-qiandao/refs/heads/main/chery-sign.js
```

之前使用 `/main/chery-sign.js` 的链接仍保留。不要删除其他 App 的签到任务，不要删除整个任务列表，也不用重新填写 token。

`.plugin` 是插件配置，不是 JavaScript；运行脚本必须使用 `.js` 地址。

## 保留原详细日志

继续按原来的方式输出：

- `🔔奇瑞汽车App签到, 开始!`
- `解析响应体：` 加签到接口原始响应
- 原来的签到结果通知与失败原因
- `[账号]获取文章[操作成功]🎉`
- `获取到文章ID列表：...`
- `解析响应体：` 加每一次分享接口的原始响应
- `[账号]分享文章[操作成功]🎉`
- `执行账号数量：...`
- `🔔奇瑞汽车App签到, 结束! 🕛 ... 秒`

不会用简化汇总替代逐条日志。不增加“今日已签到就跳过”的新分支，不改变原配置数组的账号执行数量。由于原作者原本将文章列表完整响应日志注释掉，该行也保持原样，不擅自开启可能含个人信息的大量响应输出。

## 保留原任务

签到 → 获取文章列表 → 分享前两篇文章。原本的 Node 青龙通知入口、移动端通知与头像配置均保持原样。

Node 环境请沿用原依赖和 `../qinglong/sendNotify` 路径；不把原脚本擅自改成另一套 Node 部署方式。原脚本已支持的移动端 Env 分支也保留。

原签到是否成功按原逻辑判断，不在本次顺便修改分享请求、任务并发、重试策略或账号去重规则。接口返回分享成功不代表一定增加积分。

## 自动获取凭据（保持已有设置）

此前发布的 `chery-capture.js` 本次没有修改。原本已能自动获取的设置继续用，仍保存在本机 `fmz200_chery_account`，不需要手填。

新安装时，将下方地址添加到 **Loon 插件列表**（不是脚本任务）：

```text
https://raw.githubusercontent.com/W925666/qirui-qiandao/refs/heads/main/qirui-qiandao.plugin
```

开启 Loon MitM 并信任证书后，正常登录奇瑞 App，打开签到页，收到获取成功通知即可。插件默认每天 08:00（手机时区）执行原完整任务。

凭据过期后需要正常重新登录并打开签到页；脚本不代替登录或处理验证码。不需要 Frida，也不需要关闭 RootHide 屏蔽。

仓库不存个人 token、HAR、手机号或 GitHub 密钥。获取脚本只写本机存储，账号请求只发往奇瑞 API。
